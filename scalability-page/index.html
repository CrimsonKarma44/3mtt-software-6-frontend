Design a globally distributed real-time betting engine with sub-100ms latency across 5 continents.

1. Multi-Regional Edge Deployment

Deploy edge clusters in major cloud regions (US-East, EU-West, AP-Southwest). Use Global Server Load Balancing (GSLB) with Anycast IP to route users to the nearest point of presence, reducing the initial handshake latency.

2. Conflict-free Replicated Data Types (CRDTs)

To handle state across continents without a central bottleneck, implement CRDTs for the betting pool. This allows local updates to be merged mathematically without coordination, ensuring consistent results once all updates have propagated.
